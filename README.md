# NIC Music

独立开发的原生 iOS 本地音乐播放器。资料库、专辑、歌手、播放列表、导入与文件管理由 SwiftUI 和原生音频模块实现；AMLL 负责逐字歌词，以及根据封面配色和实际播放音量变化的动态背景。

> 当前为开发测试版，最低支持 iOS 26.0。Apple Music 风格是界面参考；本项目不提供 Apple Music 账号登录、订阅曲库或流媒体服务。

## 功能

- **元数据导入**：歌名、艺人、专辑等信息读取自音频标签，不拿文件名代替歌名；提供导入进度及逐项失败反馈。
- **文件夹与专辑**：递归识别子文件夹，优先沿用文件夹的专辑组织；平铺音乐按专辑和专辑艺人元数据分类。后续补入同专辑歌曲时复用已有目录。
- **独立播放列表**：每个播放列表保存自己的音频副本。有文件名编号时按编号排序，否则按艺人、专辑日期、碟号和曲序排序。
- **播放列表封面与置顶**：自定图片优先；默认封面将列表名排入固定渐变背景。播放列表页一排三张，置顶列表同时出现在资料库首页最上方。
- **应用内副本**：音频复制到应用的 `Documents/Music`，按专辑或播放列表存放，保留原始音频字节。只有确认导入完成且可播放后，才应清理源文件。
- **封面**：优先内嵌图片，其次同目录 `cover` 图片；支持手动静态／视频封面，以及文件夹中的指定动态封面文件。
- **逐字歌词**：离线 AMLL TTML 与 LRC，支持文件内已有的翻译和发音显示开关，不包含自动翻译生成服务。
- **动态背景**：AMLL MeshGradient 读取封面颜色，使用实际音频能量调整流速和轻微缩放；暂停、进入后台或开启减少动态效果时停止动态渲染。
- **图片文件约定**：歌手目录内 `folder.xxx` 为头像，专辑目录内 `cover.xxx` 为静态封面；自定图片按同样约定保存。MP4 仅在播放界面使用，不替代列表静态封面。
- **本地搜索**：彩色分类卡片浏览本地音乐，可搜索歌曲、专辑和歌手。设置在资料库左上角；搜索、设置和歌手页不放导入入口。
- **专辑与歌手**：专辑一排两张，可按名称、发行时间、歌手排列。歌手列表显示圆形头像、专辑数和歌曲数，文件夹导入可读取 `folder.xxx` 头像，也可单独设置。
- **专辑信息**：展示实际可读取的艺人、发行日期、厂牌、版权和音质。
- **原生界面**：资料库、播放列表、专辑、歌手四个入口，搜索独立置右；应用自定义玻璃使用 clear 材质。图标采用经典红色与薄玻璃音符。
- **导入诊断**：设置显示版本与构建号、最近导入状态，可复制本地诊断；诊断不包含歌曲标题、源文件路径或音频内容，也不会自动上传。

## 测试安装包

在 [GitHub Releases](https://github.com/NICPA314/NIC-Music/releases) 中直接下载 `NIC-Music-版本-build构建号.ipa` 附件，无需解压。IPA 未签名，需要自行签名后安装；旁边的 `SHA256.txt` 可用于校验文件。

[`Native iOS IPA` GitHub Actions](https://github.com/NICPA314/NIC-Music/actions/workflows/native-ios.yml) 仅在构建和自动化测试通过后发布测试包，运行摘要提供 IPA 直达链接。模拟器截图、测试结果与构建日志单独保留在 Actions 中。多端桌面构建工作流已移除。

构建检查包括设备与模拟器编译、导入／元数据／专辑归类／独立副本／播放测试，以及系统文件选择器界面测试。具体状态以对应构建记录为准，不能将编译通过视为真机功能验证。

## 开发

原生工程位于 [`native-ios/`](native-ios/README.md)，使用 Xcode 26+、XcodeGen 和 Node.js。离线歌词资源构建及 Xcode 工程生成步骤见该目录的说明。

这是持续开发中的测试项目。真机文件提供器、后台播放、歌词同步及不同系统上的视觉表现仍需设备验证；iOS 27 尚未完成真机验证。当前没有在线音乐服务、自动联网补全标签、播放列表手动排序或随机／循环模式。
